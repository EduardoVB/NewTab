NewTabCtl Reference

NewTab is a tab control for VB6. It is a drop-in replacement for the Microsoft SSTab control: an SSTab placed on a form can be replaced with a NewTab and the form keeps its tabs, captions, pictures and contained controls, and the code that uses the SSTab members keeps working. It was formerly called SSTabEx.

Beyond SSTab, it adds:
- Five styles (Style): the two of SSTab (tabbed dialog and property page), TabStrip, Flat and Windows (drawn with the Windows visual styles).
- Twelve tab orientations (TabOrientation), including tabs at the right or bottom end of a side, and side tabs with horizontal captions.
- Themes (Theme): named sets of appearance settings. 83 are built in, and custom themes can be saved to a file, to the registry or to the form.
- Two TDI modes (TDIMode), "Tabbed Document Interface": one where each tab is a copy of a set of controls, and one where each tab hosts a form, like a tabbed MDI.
- Close buttons (CloseButton), a new tab button (NewTabButton), and a scrolling tab strip with a tab list (TabsOverflow).
- Tab reordering by dragging (CanReorderTabs).
- Icons from icon fonts (IconCharHex), also in color (IconInColor), besides pictures.
- Hover highlighting with many options (HighlightMode), and animated effects.
- Full RightToLeft support, in every orientation and style.
- DPI awareness: sizes in pixels are scaled with the DPI, and tab pictures are scaled (ScalePicturesForDPI).
- Adding and removing tabs at run time (AddTab, RemoveTab), and helpers for the contained controls (ControlSetTab, FitToClientArea).

Working with contained controls.
Like with SSTab, each contained control belongs to one tab, and the controls of the tabs that are not selected are moved far to the left (LeftOffsetToHide) to hide them. So:
- At run time, don't read the Left of a contained control to know where it is: use ControlLeft, and ControlMove instead of its Move method.
- To put a control of the form into a tab by code, first set its Container to the NewTab and then call ControlSetTab:

Set Text1.Container = NewTab1
NewTab1.ControlSetTab Text1, 2

- A control created with Controls.Add goes in the same way. To handle its events, declare a WithEvents variable of its type:
Private WithEvents mButton As CommandButton

Private Sub Form_Load()
    Set mButton = Controls.Add("VB.CommandButton", "cmdNew")
    Set mButton.Container = NewTab1
    NewTab1.ControlSetTab mButton, 1
    mButton.Move NewTab1.ClientLeft + 120, NewTab1.ClientTop + 120
    mButton.Visible = True
End Sub

- The space inside the body is given by ClientLeft, ClientTop, ClientWidth and ClientHeight, in twips. FitToClientArea makes a control fill that space and keeps it fitted.

Differences with SSTab that matter when porting code
- Removing tabs that still hold controls raises error 1390, not 380.
- At run time all the tabs can be removed or hidden. Then Tab is -1.
- RemoveTab and AddTab exist; with SSTab the only way was changing Tabs.
- TabHeight is calculated automatically while AutoTabHeight is True, the default for a new control. Setting TabHeight turns it off.
- The default Style of a new control is Windows (ntStyleWindows), not tabbed dialog.
- Many properties have an Auto value that follows Style. A theme sets fixed values instead.
- Errors raised for invalid arguments follow VB's rules: error 5 from methods, error 381 for an invalid tab index in a property, error 380 for an invalid property value. The control's own errors are numbered from 1380.

    • NewTab control

    Tab control for VB6, compatible with SSTab.

    The control shows a strip of tabs and a body. Each tab has its own set of contained controls, and only the controls of the selected tab are visible.

    The current tab is set or read with the Tab property. Changing it raises the BeforeClick, Click and TabChange events, in that order.
    The properties that start with Tab and take an index, like TabCaption or TabVisible, work on one tab. Their index parameter, nTab, can be the tab index (zero based), its TabKey, or its TabCaption.
    The properties without an index that refer to one tab, like Caption or Picture, work on the selected tab, as they do in SSTab.

    AutoRelocateControls Property

    Type: NTAutoRelocateControlsConstants

    Description:

    Returns or sets a value that determines whether the contained controls are moved automatically when the body changes its position.

    The body moves when the tab strip changes: another TabOrientation, more or fewer rows of tabs, a different TabHeight, Style or font. The contained controls are moved by the same amount, so they keep their place relative to the body.

    Values:
    ntRelocateAlways (default): the controls are moved whenever the body moves.
    ntRelocateOnTabOrientationChange: the controls are moved only when TabOrientation changes.
    ntRelocateNever: the controls are never moved. Choose this value if your code places them, for example in the Resize event.

    Note: after changing by code something that moves the body, place new controls reading ClientLeft and ClientTop, which applies the pending change first. A control moved to fixed numbers before that is moved again when the control redraws.

    See Also:

    ClientLeft property

    AutoTabHeight Property

    Type: Boolean

    Description:

    Returns or sets a value that determines whether the height of the tabs (TabHeight) is calculated automatically.

    When True, the height is calculated from the Font, TabPaddingHeight, the icons and pictures of the tabs, the close button and the other glyphs that the tabs can show. It is recalculated whenever any of these change.
    Setting TabHeight sets AutoTabHeight to False.

    The height is calculated for captions of one line. With WordWrap set to True, a caption that doesn't fit in the length of the tab is split in two lines but the tab doesn't grow, so the second line can be cut. That happens only when the length of the tab doesn't come from its caption: with ntTWEqualWidth, TabsPerRow, a fixed width, or the side orientations. In those cases set WordWrap to False (the caption gets an ellipsis) or set TabHeight by hand.

    The default is True for new controls. Forms saved with earlier versions of the control, and forms converted from SSTab, keep False.

    BackColorSelectedTab Property

    Type: Long

    Description:

    Returns or sets the color of the selected tab and of the body (the area where the contained controls are).

    BackStyle Property

    Type: NTBackStyleConstants

    Description:

    Returns or sets which parts of the control are left transparent, so that the container shows through.

    Values:
    ntOpaque (default): everything is painted.
    ntTransparentBackOnly: only the area painted with BackColor is transparent. The tabs and the body are painted.
    ntTransparent: the area of BackColor and also the body and the selected tab are transparent. The inactive tabs are painted.

    The transparent parts don't receive mouse clicks: they go to what is behind.
    With ntTransparent the tabs can't be drawn with the Windows visual styles, and the Windows style is drawn like the TabStrip style.
    At run time, when no tab is visible and there is no new tab button, the whole control is transparent.

    CanReorderTabs Property

    Type: Boolean

    Description:

    Returns or sets a value that determines whether the user can change the order of the tabs by dragging them with the mouse.

    It works in all the orientations, with one or several rows of tabs, and with RightToLeft.
    While a tab is dragged the others open a gap where it will fall, and the order changes when the mouse button is released. Before that the BeforeTabReorder event is raised, where the move can be canceled or its destination changed, and after it the TabReordered event.
    TabMovable keeps a tab in its place. The new tab button and the tab 0 of the TDI modes never move.

    When the order changes, the tab indexes change. To find a tab after the user moved it, use its TabKey, TabData or TabTag, or its original index with FindTab. GetTabsOrder and SetTabsOrder save and restore the order, and need this property to be True.

    ChangeControlsBackColor Property

    Type: Boolean

    Description:

    Returns or sets a value that determines whether the BackColor of the contained controls is changed to the background color of the selected tab. The default is True.

    The controls that are changed are the ones whose BackColor is the color the tab control gave them before (at first, the same color as the body). A control with a different BackColor is left as it is.
    So when BackColorSelectedTab changes, a theme is applied, or a tab with a color of its own (TabCustomColor) is selected, those controls follow the color of the body.
    The ChangeControlBackColor event allows to exclude some controls.

    When the body is drawn with the Windows visual styles, it is lighter than the button color that the controls have. Then:
    - The controls with a window (CheckBox, OptionButton, Frame and others) are painted with the body behind them. This needs subclassing: with SubclassingMethod disabled or set to one of the "only UserControl" values they keep the button color.
    - The opaque Labels with that color are changed to a transparent BackStyle. This is done also at design time, and the change is saved in the form.

    See Also:

    ChangeControlsForeColor Property

    Type: Boolean

    Description:

    Returns or sets a value that determines whether the ForeColor of the contained controls is changed to the caption color of the selected tab. The default is True.

    Like with ChangeControlsBackColor, only the controls whose ForeColor is the color that the tab control gave them before are changed.
    The color they get is:
    - the ForeColorSelectedTab of the tab, or the one of the control when it was set by hand (or by a theme) and the selected tab has no highlight background. It is given as it is;
    - otherwise, the caption color, if it has enough contrast against the background of the selected tab. If it doesn't, the controls get black or white, whichever reads better. When the selected tab has a highlight background (HighlightModeSelectedTab), its caption color was chosen for that background and not for the body, so it is checked too.
    The ChangeControlForeColor event allows to exclude some controls.

    With the Windows visual styles, Windows draws the captions of CheckBox, OptionButton and Frame controls in the color of the theme, ignoring their ForeColor. With subclassing (see SubclassingMethod) the control draws them with their ForeColor: the VB ones, and the check boxes and option buttons that are Windows buttons, like the ones of VBCCR. Without subclassing they stay in the color of the theme, which can't be read over a dark body.

    Type: NTCloseButtonPositionConstants

    Description:

    Returns or sets where the close buttons are shown.

    HighlightMode Property

    Type: NTHighlightModeFlagsConstants

    Description:

    Returns or sets how the inactive tabs are highlighted while the mouse is over them.
    The selected tab has its own setting, HighlightModeSelectedTab.

    The value is a combination of the flags of NTHighlightModeFlagsConstants:
    - The background, one of: ntHLBackgroundPlain (4), ntHLBackgroundGradient (2) or ntHLBackgroundDoubleGradient (3). ntHLBackgroundLight (8) makes it lighter.
    - The caption: ntHLCaptionBold (16), ntHLCaptionUnderlined (32).
    - The size and position: ntHLExtraHeight (256) makes the tab taller by HighlightTabExtraHeight, ntHLShiftCaption (1024) moves its contents by HighlightTabCaptionShift, ntHLWidenTab (2048) widens it on both sides.
    - Flat style only: ntHLFlatBar (64) shows the bar, ntHLFlatBarGrip (128) adds a grip to the bar, ntHLFlatDrawBorder (512) draws a border around the tab, ntHLRoundBottom (4096) rounds also the corners of the tab on the side of the body, ntHLFlatShapeInactive (8192) gives the inactive tabs, also when the mouse is not over them, the shape of the highlighted one (only for this property).
    ntHLNone (1) is no highlight, and ntHLAuto (0), the default, lets Style decide:
    - Flat: background gradient, light, and the bar.
    - Windows: plain background.
    - Tabbed dialog, property page and TabStrip: none, like the original controls.

    While the tabs are drawn with the Windows visual styles, any background flag shows the "hot" look of Windows, and the gradient and light flags make no difference. The caption, size and position flags work in every style.
    The Highlight page of the property pages disables the flags that have no effect with the current settings.

    IconAlignment Property

    Type: NTIconAlignmentConstants

    Description:

    Returns or sets where the icon or picture of each tab goes, with respect to the caption.

    Values:
    ntIconAlignCenteredBeforeCaption (default): before the caption. When the caption is aligned to a side, the icon is centered in the free space on its side if there is enough room, so it doesn't look stuck to the caption.
    ntIconAlignBeforeCaption: right before the caption, the two aligned together.
    ntIconAlignCenteredAfterCaption and ntIconAlignAfterCaption: the same, after the caption.
    ntIconAlignStart: at the start edge of the tab; the caption is aligned in the remaining space.
    ntIconAlignEnd: at the end edge of the tab.

    "Before" and "start" follow the reading order of the caption: with RightToLeft they are on the right, and in the Left and LeftTop orientations, whose captions read from bottom to top, they are below.
    With the caption centered (CaptionAlignment), the "Centered" values draw the same as the others.
    With the icon above or below the caption, the captions of all the tabs with an icon are at the same height, and the icons are centered in the height of the largest one. A tab without icon centers its caption.

    TabWidthStyle Property

    Type: NTTabWidthStyleConstants

    Description:

    Returns or sets how the width of the tabs is decided.

    Values:
    ntTWAuto (default): it depends on Style, and on the TDI mode and the new tab button. See below.
    ntTWEqualWidth: all the tabs have the same width: the width of the control divided by TabsPerRow. In earlier versions this value was called ntTWFixed.
    ntTWTabCaptionWidth: each tab is as wide as its caption and icon need, within TabMinWidth and TabMaxWidth. A new row starts every TabsPerRow tabs. If a row doesn't fit, its tabs are made narrower.
    ntTWTabStripEmulation: like the TabStrip control: each tab as wide as its caption, and when they don't fit in one row, they are distributed evenly in several rows and stretched so that every row fills the width of the control. If they fit in one row, they are not stretched.

    ntTWGeneralFixedWidthFillRows: all the tabs start with the width of TabGeneralFixedWidth, and the rows are filled as with ntTWTabCaptionWidthFillRows.

    - in a TDI mode, or with the new tab button: ntTWTabCaptionWidthFillRows;
    - tabbed dialog: ntTWEqualWidth, like SSTab;
    - property page: ntTWTabCaptionWidth, like SSTab;
    - TabStrip: ntTWTabStripEmulation;
    - Flat and Windows: ntTWStretchToFill.

    TDIMode Property

    Type: NTTDIModeConstants

    Description:

    Returns or sets whether the control works as a TDI (Tabbed Document Interface) and in which mode. In a TDI mode the user opens and closes tabs, and the control handles them.

    Values:
    ntTDIModeNone (default): normal mode.
    ntTDIModeControls: each tab is a "document" made of the controls of tab 0, which is a template and is hidden at run time. Put the controls on tab 0 at design time, all of them as control arrays with Index 0. For each new tab the controls are loaded again (with Load) and placed on it. Your code tells the copies apart by their Index. A new tab button ("+") opens new tabs.
    ntTDIModeForms: the NewTab hosts the other forms of the program, like an MDI form but with tabs. Place it on the main form, sized to fill it; every form that is shown afterwards opens in a new tab, and closing the tab unloads it. Tab 0, called "Home", is always there and can't be closed: it can hold controls of the main form, like a menu of the program.

    It can only be changed on a control that was just placed on the form, with its initial tabs and no contained controls. At design time the property pages say why it can't be changed; at run time error 1391 is raised.
    At run time it can be set on a control created with Controls.Add, before the control is shown. For the Controls mode, set the mode, then put the template controls into tab 0 with Container and ControlSetTab; the mode starts when the control is shown.

    In the TDI modes:
    - AddTab and RemoveTab are not available, and Tabs can't be changed at design time.
    - The mode decides which tabs have a close button.
    - TDIBeforeNewTab, TDINewTabAdded, TDIBeforeClosingTab and TDITabClosed tell when tabs are opened and closed. Their TabNumber parameter identifies a tab for as long as it lives; nTab is its current index, which changes when the tabs are reordered.
